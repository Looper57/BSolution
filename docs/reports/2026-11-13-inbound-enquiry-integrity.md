# Inbound enquiry integrity

The German, Polish and Czech homepages displayed a success message after local field checks without sending any request. Replace those three placeholder forms with the existing shared contact form, including Turnstile, the honeypot, pending state and error recovery. The standalone contact page uses the same extracted component. Success requires both an HTTP success and an explicit success response. Errors preserve the visitor's brief. This is a repair of the voluntary inbound enquiry path, with no outbound messages or new marketing routes.

The API previously discarded company, phone and enquiry type even though the standalone form submitted them. Validate and preserve these optional fields in the existing HTML/plain-text notification, with length bounds, control-character rejection and HTML escaping. Older clients without the fields remain supported. Request deduplication includes the full accepted brief. Existing recipients, email identity, security configuration, terms and fees stay unchanged.

After the existing provider accepts a message, the structured contact log includes only the bounded category hiring/candidate/other/unspecified. Failed, honeypot and replay responses do not add another category-counted acceptance. No names, emails, phone numbers, companies or message bodies are added to logs. There are no new cookies, visitor identifiers, external trackers or custom analytics-plan dependencies. This supports counting self-declared employer enquiries separately from candidate traffic; it does not establish delivery to the inbox, lead quality, an originating SEO page, organic attribution or a signed mandate. Group accepted log records by enquiryType and requestId within the configured log retention; assess qualification and mandates from the received briefs through the normal business process.

Regression coverage adds six unit cases for optional details, legacy clients and safe rendering, extends the API-to-provider payload/log privacy proof, and adds three native browser journeys. Each browser journey intercepts only the local contact endpoint: provider failure and a200/false response preserve the form, and only the final200/true response shows success. No real email is sent for testing. Final source-specific CI and public deployment evidence are recorded in the shared roadmap.
